# Решение

## Сколько заняло

Около 2 часов.

## Что сделано и что не успел

Сделан экран матчей: загрузка, карточки, фильтры, избранное, обновление, индикатор загрузки, ошибки с повтором и пустое состояние. Исправлены готовые `useFavorites` и `UpdatedAgo`, звёздочка подключена через существующий `FavoriteButton`.

Дополнительно добавлен поиск по названию любого из двух клубов: он помогает быстро найти матч и работает вместе с фильтрами. Избранное хранится только до перезапуска приложения; на физическом телефоне приложение не проверялось.

## Решения

- В «Предстоящие» включены `scheduled` и `postponed`: перенесённый матч ещё должен состояться. В «Завершённые» попадает только `finished`, а `live` и неизвестные статусы остаются в «Все». Фильтрация идёт по статусу, а не по дате.
- Счёт `0:0` отображается как результат, отсутствующий счёт — как прочерки. При `startsAt: null` показано «Дата и время уточняются»; остальные даты переводятся в часовой пояс устройства. Для текущего матча отображается минута, если она передана.
- Исходный `MATCHES_URL` сохранён. Он возвращает 404, поэтому только при этом ответе подставляются локальные моки с явной пометкой; каждое обновление снова обращается к серверу. Другие ошибки не маскируются моками, ожидание ограничено 15 секундами, а при неудачном обновлении предыдущие данные остаются на экране.

## Баги из части 2

1. Звёздочки: `indexOf` возвращает `-1` для отсутствующего ID и `0` для первого элемента; преобразование в `Boolean` давало обратный ожидаемому результат. Кроме того, массив менялся на месте и передавался обратно с той же ссылкой, поэтому React мог пропустить обновление. Проверка заменена на `includes`, а переключение использует функциональный `setState` с новым массивом.
2. «Обновлено N сек назад»: интервал захватывал начальное значение `seconds`, постоянно устанавливал одно и то же число и не использовал `since`. Теперь прошедшее время вычисляется от момента последней успешной загрузки, интервал пересоздаётся при изменении `since` и очищается при размонтировании.

## Как я использовал ИИ

Использовал Codex как агента для работы с репозиторием: изучения задания и существующего кода, реализации экрана, исправления ошибок в хуках и проверки результата. Основную часть кода написал агент. Я определял объём и последовательность изменений: сначала простой экран с моками, затем фильтры, избранное и оставшиеся состояния загрузки; отдельно уточнял поведение при ошибках и просил объяснить реализацию избранного.

Результат дорабатывался по моим замечаниям.

Технические проверки также выполнял Codex: TypeScript, сборки для Web/iOS/Android и браузерные сценарии через Playwright. Проверялись не только отображение данных, но и переключение фильтров, независимость звёздочек, сброс таймера, пустой ответ, ошибки и повторная загрузка. Для воспроизведения разных ответов API использовалась подмена сетевых запросов; исходный адрес и его реальный ответ 404 проверялись отдельно. Эти браузерные проверки запускались вне репозитория и не заменяют постоянный набор автотестов или проверку на физическом устройстве.

## Что улучшил бы, будь ещё 2 часа

Добавил бы сохранение избранного между запусками и постоянные автотесты для фильтров, загрузки и таймера. Проверил бы экран в Expo Go на физическом телефоне и уточнил рабочий адрес API, чтобы убрать необходимость в моках (на момент выполнения работы по указанной в конфиге ссылке возвращалось 404).
